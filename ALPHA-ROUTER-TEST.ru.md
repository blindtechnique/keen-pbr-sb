# Приёмка alpha на Keenetic

Alpha устанавливается только на тестовый роутер или при наличии физического
доступа. Перед началом скачайте полный backup keen-pbr-sb и экспорт
конфигурации KeeneticOS.

Адрес роутера и SSH-порт не фиксированы. Используйте фактический локальный или
удалённый адрес своего устройства; не подставляйте автоматически
`192.168.1.1`, если сеть настроена иначе.

## 1. До установки

Запишите:

- текущий commit/артефакт alpha;
- версию установленного пакета;
- какие нативные VPN-серверы включены;
- активные исходящие соединения и участники failover;
- время начала проверки.

Убедитесь, что SSH работает и ключ относится именно к этому роутеру:

```powershell
$RouterHost = "адрес-роутера"
$SshPort = 222
ssh -p $SshPort "root@$RouterHost"
```

## 2. Установка

1. Дождитесь зелёного workflow ветки `alpha`.
2. Запустите `install-alpha-build.bat` из каталога MyKeenPBR.
3. Проверьте SHA256 и имя скачанного IPK в выводе установщика.
4. После `OK-INSTALLED` обновите страницу панели один раз через `Ctrl+F5`.

Установка считается неуспешной, если для запуска маршрутизации требуется
второй запуск установщика, второй restart сервиса или повторный apply без
изменения конфигурации.

## 3. Сервис после установки

В SSH:

```sh
/opt/etc/init.d/S80keen-pbr status
pid="$(cat /opt/var/run/keen-pbr.pid 2>/dev/null)"
echo "PID=$pid"
kill -0 "$pid"
tail -n 150 /opt/var/log/keen-pbr.log
```

Ожидается один живой PID, доступная панель и отсутствие циклических restart,
resolver/firewall reconcile, `iptables-restore ... COMMIT`, stale PID и
повторяющихся уведомлений SSE limit.

## 4. Apply и жизненный цикл

1. Измените безопасный параметр, сохраните и дождитесь успешного завершения.
2. Верните исходное значение. Плашка несохранённых изменений должна исчезнуть.
3. Выполните один штатный restart из дашборда.
4. Убедитесь, что DNS, маршруты и управляемые транспорты восстановились после
   этого единственного restart.
5. Некорректный черновик должен быть отклонён без замены действующего
   `/opt/etc/keen-pbr/config.json`.

## 5. Маршрутизация и DNS

Проверьте по одному реальному домену для:

- direct;
- nfqws2;
- нативного WG/AWG;
- sing-box транспорта;
- urltest/failover;
- доменного списка с согласованным DNS detour;
- route-only IP companion.

Для каждого зафиксируйте внешний IP, задержку и результат встроенной проверки
маршрута. Не должно быть DNS_PROBE_FINISHED_NO_INTERNET, долгого первого
открытия 2ip/whatismyipaddress или утечки через WAN при kill-switch.

## 6. Нативные VPN-клиенты

Проверяйте только реально включённые на роутере серверы: WG/AWG, IKEv2,
SSTP, L2TP или IKEv1. Для каждого клиента:

- локальные ресурсы доступны;
- direct/nfqws2 сайты открываются;
- списочные маршруты идут через выбранный туннель;
- DNS работает после reconnect клиента и restart keen-pbr-sb;
- произвольная подсеть клиента обнаруживается из NDMS, а не из фиксированного
  диапазона в коде.

Подтверждённый IKEv2 baseline не изменяйте во время диагностики другого
протокола.

## 7. Failover и восстановление firewall

1. Остановите основной участник группы.
2. Новые соединения должны перейти на резервный; для режима
   `delete_on_failure` очищаются только потоки отказавшего выхода.
3. Верните основной участник. В preferred-primary режиме новые соединения
   возвращаются на него, работающие резервные потоки не обрываются.
4. Проверьте, что управляемые route/firewall/SNAT правила восстановлены и не
   дублируются.

## 8. WhatsApp/Meta recovery

На Android после 2-3 минут простоя:

1. отправьте три сообщения с интервалом;
2. проверьте первую и вторую галочки;
3. выполните входящий и исходящий звонок;
4. повторите после restart/apply и восстановления туннеля.

Цель для уже зависшего потока - доставка примерно за 5-10 секунд после
подтверждения зависания. Активный двусторонний звонок не должен обрываться.

## 9. Что приложить к дефекту

- commit и имя IPK;
- точное время и часовой пояс;
- действие перед сбоем;
- диагностический архив из панели;
- последние 200 строк `/opt/var/log/keen-pbr.log`;
- помог ли один штатный restart (не выполняйте второй до сбора данных).

Не сбрасывайте Entware до выгрузки диагностики: иначе исчезнут журнал и
runtime-состояние, необходимые для разбора причины.
