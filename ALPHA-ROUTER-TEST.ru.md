# Проверка кандидата Main / Alpha на Keenetic

Перед установкой сохраните резервную копию настроек keen-pbr-sb и KeeneticOS.
Установку и проверку выполняет владелец тестового роутера. Успешная сборка
не заменяет эту проверку и не означает продвижение в Latest.

## Диагностика сайтов и смена VPN на группу: регрессии 17.09.2026

Проверять после установки исправленного IPK; результаты локальных проверок не заменяют эту приёмку.

- Стандартный nfqws2-keenetic 1.2.8 с автоматическим IPV6_ENABLED=0 отображается как стандартная стратегия без повторного применения и перезапуска nfqws2.
- В проверке сайта отдельно видны включение в nfqws (зелёным), исключение (синим) и отсутствие в списках; адрес выделен жирным. Технические пояснения свёрнуты.
- Реестр: блокировка красная, отсутствие синее, белый список зелёный только при соответствующем ответе сервиса.
- В диагностике правил видны найденные настроенные каталожные/пользовательские списки, пользовательский псевдоним VPN и статус. Список без привязанного правила не выдаётся за работающий VPN-маршрут.
- Переключить одно тестовое правило с отдельного AmneziaWG на группу с резервным VLESS sing-box и обратно. Проверить успешное завершение применения и фактический путь сайта; служба должна оставаться работающей.
- При наличии оставшегося служебного IPv6-маршрута после прежнего неудачного применения сервис убирает его сам. Не удалять системные маршруты вручную и не сбрасывать Entware для этой проверки.
- Сохранить результат проверки на устройстве перед отдельным решением о продвижении в Latest.

## Ночное обновление списков и сохранение выключения VPN: 18.09.2026

- На тестовом роутере обновить списки через панель: после завершения задачи keen-pbr остаётся в состоянии «Работает», ранее выбранный VPN-маршрут продолжает использоваться. Отдельно проверить ближайшее плановое обновление списков.
- Выключить один управляемый VLESS переключателем панели. После обычного перезапуска transport-manager и после перезагрузки тестового роутера этот VLESS остаётся выключенным; другие включённые подключения продолжают запускаться. Проверить в режимах isolated и shared.
- Включить этот VLESS обратно и проверить сохранение включённого состояния после перезапуска.
- Перезапуск подключения и временная остановка для установки sing-box не должны менять сохранённый автозапуск. Нативные интерфейсы Keenetic/Netcraze этими проверками не изменяются.
- Не удалять NAT-цепочки вручную для воспроизведения ночного сбоя на роутере: случай ожидающего восстановления SNAT проверяется изолированной регрессией. Наличие маршрута или процесса само по себе не подтверждает путь трафика.
- Старые ручные выключения не записывались в auto_start. При обновлении их прежнюю настройку автозапуска автоматически не переписываем: для такого подключения сохраните выключенный автозапуск в его настройках. Это не требует временно включать VPN.
