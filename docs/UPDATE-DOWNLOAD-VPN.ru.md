# Загрузка обновлений через VPN

Локальная реализация; перед выпуском требуется проверка IPK на роутере.

В «Настройки → Обслуживание» настройка «Скачивать обновления через» выбирает
обычный маршрут роутера, применённый VPN или группу. «Сохранить способ загрузки»
сохраняет только эту настройку, без перезапуска служб и применения правил.
Она действует и при обновлении из панели, и при запуске штатного установщика
из консоли. Имена берутся из применённой конфигурации, не из черновика.

- Обычный маршрут не обязательно означает WAN: действующие правила роутера
  сохраняют силу. DNS-запросы выполняются обычным DNS роутера.
- Для VPN/группы загрузчик использует выбранный интерфейс и его метку
  маршрутизации. Между файлами выбранный участник группы определяется заново.
  Неисправный путь не заменяется обычным маршрутом. Проверка не обещает, что
  удалённый сервер VPN или GitHub обязательно ответят.
- HTTPS и проверка подписанного манифеста остаются обязательными. Файлы пишутся
  потоком во временный файл, без полной дополнительной копии IPK в RAM.
  Ошибка сети, диска или HTTP не заменяет существующий файл частичным ответом.
- Выбор хранится в `/opt/etc/keen-pbr/update-outbound`. Пустое значение означает
  обычный маршрут. Удаление выбранного VPN не сбрасывает настройку незаметно:
  нужно явно выбрать другой путь.
  Файл сохраняется при обновлении и восстановлении прежней конфигурации.
  Если откатить сам пакет на старую версию без этой функции, та версия не сможет
  использовать выбранный путь: сохранение файла не добавляет поддержку в старый код.
- Если служба временно не отвечает, панель сохраняет и показывает выбранный путь.
  Можно повторить получение списка VPN либо вручную выбрать и сохранить обычный
  маршрут. Сам отказ службы не разрешает загрузчику обойти выбранный VPN.
- Настройка относится к файлам обновления keen-pbr-sb, а не ко всему трафику
  роутера. Загрузка зависимостей самим `opkg` и первоначальное скачивание
  установщика внешней командой `wget`/`curl` ею не управляются.

Для разового запуска **после установки версии с этой функцией** можно указать
технический тег существующего выхода, например `KEEN_PBR_UPDATE_OUTBOUND=gr1`,
в окружении штатной команды обновления. Явное `KEEN_PBR_UPDATE_OUTBOUND=''`
выбирает обычный маршрут только для этого запуска. Не нужны `/etc/hosts`,
глобальный `.curlrc`, жёстко заданные IP GitHub или дополнительные правила firewall.

## Приёмка на Giga/Ultra

1. Выбрать отдельный AWG, проверить метаданные выпуска и обновление из панели.
2. Выбрать группу AWG + sing-box; проверить загрузку через обоих участников.
3. Проверить ту же сохранённую настройку при обновлении из консоли.
4. Остановить выбранный выход: загрузка должна отказать до изменения пакета,
   службы должны оставаться работать. WAN не должен получать соединение загрузки.
5. Проверить смену участника во время скачивания, удалённый выход, наличие
   неприменённого черновика, разрыв сети, отказ записи и сохранение выбора после обновления.
6. Проверить перенаправления GitHub, отказ от HTTP, подпись, ограничение размера,
   мало места в `/opt` и `/tmp`. Не считать локальные тесты заменой этой приёмки.

## Дополнительная проверка nfqws

Проверяется собранная команда запуска, включая повторение TCP/QUIC-профилей:
пустые действия, неправильные объявления blob и повторные имена (включая встроенные).
Проверка файлов понимает смещения `+N@путь` и старую запись без `@`.
Пользовательские Lua-функции не объявляются отсутствующими по неполному списку
или регулярному выражению. Lua при этой проверке не исполняется; штатная проверка
установленным движком остаётся отдельной, а работа обхода проверяется трафиком.
