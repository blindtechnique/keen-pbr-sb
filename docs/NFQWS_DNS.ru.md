# Зашифрованный DNS в стратегиях nfqws2

В Safe, Balanced, Max и 13 прежних пресетах проекта (в том числе «Версия 8» и старый `default`) добавлена обработка **соединения с резолвером**, а не доменных имён, которые через него запрашивают. Две точные копии штатных настроек Entware — `default (nfqws2 1.2.8)` и `default (nfqws2 1.3.1)` — и пользовательские сохранённые профили не меняются.

| Соединение | Когда применяется правило |
|---|---|
| DoH по HTTPS/TCP, порт 443; DoT по TCP, порт 853 | В TLS ClientHello видно имя публичного резолвера из списка. Включены, в частности, OpenDNS и Яндекс. Совпадения только по общему IP на 443 нет. |
| DoT по TCP, порт 853 | Дополнительная ветвь по выделенным адресам резолверов IPv4/IPv6. Обе ветви сохраняют исключения по домену и IP. |
| Обычный DNS на 53, DoH поверх HTTP/3, DoQ | Нового правила нет. Политика IPv6 остаётся такой, какую выбрал владелец. |

Здесь использована идея [раздельных фильтров nfqws-menu](https://github.com/rndnaame/nfqws-menu/blob/19485244a8731ac01e7b52896fc25a425c26c051/strategies/dns_filter_nfqws2), а не меню установки. Действие касается только исходящего TLS ClientHello: исходные байты передаются двумя последовательными частями. Подмена имени, ложные TLS-пакеты и обработка всего HTTPS не добавляются. Имена и адреса Яндекса можно сверить по [данным провайдера](https://dns.yandex.com/).

**Проверять надо две разные вещи.** Сначала проверьте, отвечает ли настроенный DoT/DoH-сервер на обычный DNS-запрос через его локальный прокси. Затем сделайте некэшированный запрос через сам маршрутизатор и посмотрите выбранные upstream для нужного домена. Если в Keenetic одному домену назначены и обычный сервер, и шифрованный, успешный ответ DoH не означает, что копия запроса не ушла открытым текстом. Применение пресета nfqws2 не удаляет обычные DNS-серверы, не меняет интернет-фильтр и не включает туннель.

Для обновления набора правьте `encrypted_dns_blocks()` в `build_scripts/build-nfqws-strategies.py`, перегенерируйте три основных профиля и выполните `python3 build_scripts/build-nfqws-strategies.py --sync-legacy-dns` для прежних. `make check-nfqws-assets` проверяет совпадение DNS-ветвей, остальные назначения старых профилей и контрольные суммы штатных копий.
